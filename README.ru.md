# TermGlass

**Минималистичный терминал в стиле «стекла» для рабочего стола.**<br>
Настоящие шеллы, разделение на панели, палитра команд, темы и выбор шелла. Сделан на Electron, xterm.js и node-pty.

Каждая панель — настоящий псевдотерминал с вашим настоящим шеллом. Никакой имитации команд: vim, nano, htop, ssh и ваш собственный промпт работают так же, как в любом другом терминале.

## Возможности

- **Настоящий терминал.** node-pty для PTY, xterm.js для отрисовки (WebGL с автоматическим запасным вариантом), truecolor, UTF-8 с корректным Unicode, мышь, bracketed paste, история до 100 000 строк, поиск, копирование и вставка.
- **Вкладки и панели.** Переименование и перетаскивание вкладок; горизонтальное и вертикальное разделение с изменением размера мышью; у каждой панели свой PTY и свой шелл.
- **Выбор шелла.** Находит установленные в системе шеллы, меняет шелл панели одним кликом с сохранением рабочей папки, открывает вкладки и панели с любым шеллом. [Подробнее](#управление-шеллами).
- **Палитра команд** (`Ctrl+Shift+P`) с нечётким поиском по командам, вкладкам, темам, шеллам и настройкам.
- **Пять встроенных тем** и свои темы в JSON с горячей перезагрузкой. Читаемость палитр проверяется тестами.
- **Все сочетания клавиш настраиваются**, есть сворачиваемая боковая панель и спокойная строка состояния.
- **Аккуратное закрытие.** Спрашивает подтверждение, только если запущена программа, и никогда на пустом приглашении; при выходе все шеллы завершаются.
- **Безопасная архитектура.** Изолированный рендерер, context isolation, строгий CSP, проверка всех IPC-сообщений и никакого канала «выполни команду». [Подробнее](#модель-безопасности).
- **Иконки промпта работают.** Установленные Nerd Fonts используются как запасные шрифты, поэтому значки Starship и Powerlevel10k отображаются.

## Установка

**Готовые пакеты** лежат на [странице Releases](https://github.com/NettixDev-ctrl/TermGlass/releases), их собирает GitHub Actions из помеченных тегом коммитов:

| Файл | Для чего |
| --- | --- |
| `termglass-*.pkg.tar.zst` | Arch Linux / CachyOS: `sudo pacman -U termglass-*.pkg.tar.zst` |
| `TermGlass-*-linux-x64.AppImage` | Любой Linux: `chmod +x` и запуск (автор его пока не запускал) |
| `TermGlass-*-linux-x64.tar.gz` | Любой Linux, распакованная сборка |
| `TermGlass-Setup-*.exe`, `TermGlass-*-portable.exe` | Windows (**не проверено**) |

В каждом релизе есть `SHA256SUMS.txt`. **Чтобы собрать из исходников самому:**

```bash
git clone https://github.com/NettixDev-ctrl/TermGlass.git
cd TermGlass
npm install
```

**Arch Linux / CachyOS** (полноценный пакет, который pacman умеет удалять):

```bash
packaging/arch/build.sh
sudo pacman -U packaging/arch/termglass-*.pkg.tar.zst
```

**Другие дистрибутивы Linux** (AppImage и tar.gz в `release/`):

```bash
npm run dist:linux
```

**Windows** (собирать на Windows; не проверено): `npm run dist:win`

**Запуск без установки:** `npm run build && npm run start`

Требования: Node.js 20+ (разрабатывалось на Node 26), компилятор C++, Python и `make` для пересборки `node-pty` под Electron (в Arch: `sudo pacman -S --needed base-devel python`). Если npm сообщает о заблокированных скриптах установки, собственный `postinstall` проекта всё равно выполняется; если `node-pty` не загружается, выполните `npm run rebuild`.

Повторный запуск `termglass`, когда он уже открыт, фокусирует окно и открывает **новую вкладку**. Поэтому его удобно вешать на глобальное сочетание, например `Ctrl+Alt+T`.

## Использование

- **Вкладки:** `Ctrl+Shift+T` новая, двойной клик или `Ctrl+Shift+R` переименовать, перетаскивание меняет порядок, средняя кнопка закрывает, `Alt+1`–`Alt+9` переход (`⌘1`–`⌘9` на macOS).
- **Панели:** `Ctrl+Shift+D` разделить вправо, `Ctrl+Shift+E` вниз, `Alt+Shift+стрелки` переносят фокус, разделитель тянется мышью (двойной клик сбрасывает).
- **Поиск:** `Ctrl+Shift+F`. **Копировать и вставить:** `Ctrl+Shift+C` / `Ctrl+Shift+V`. Обычные `Ctrl+C`, `Ctrl+D` и `Ctrl+Z` всегда доходят до шелла.
- **Ссылки:** Ctrl+клик открывает `http(s)`-ссылки из вывода.

По умолчанию сочетания не конфликтуют с терминальными программами: в Linux и Windows большинство используют `Ctrl+Shift`. Всё можно переназначить в **Настройки → Keyboard**.

## Управление шеллами

**Поиск** работает в главном процессе и повторяется по запросу (*Rescan*). В списке только существующие и запускаемые файлы, без дублей по исполняемому файлу: `/bin/bash` и `/usr/bin/bash` это один шелл, а `sh` остаётся отдельной записью, даже если это ссылка на bash.

| Платформа | Источники |
| --- | --- |
| Linux / macOS | ваш login-шелл из базы пользователей, `$SHELL`, все записи `/etc/shells` и поиск в `PATH` и типовых каталогах (`/usr/local/bin`, Homebrew, `~/.cargo/bin`, `~/.nix-profile/bin`, `/snap/bin`) для bash, zsh, fish, nu, dash, sh, elvish, xonsh, ksh, mksh, ash, tcsh, csh, pwsh, osh, ysh, murex, ion, yash и rc. Заглушки вроде `nologin`, `git-shell` и `systemd-home-fallback-shell` игнорируются |
| Windows | PowerShell 7+ (PATH, `Program Files\PowerShell\*`, алиас из Store), Windows PowerShell, cmd.exe, Git Bash (папки установки или путь от `git.exe` в PATH; `System32\bash.exe` — это лаунчер WSL, и как Git Bash он не предлагается), шеллы вида MSYS2/Cygwin из PATH и дистрибутивы WSL из `wsl.exe --list`. Для *запущенных* дистрибутивов добавляются и их login-шеллы; остановленные дистрибутивы никогда не запускаются ради поиска |

**Шелл системы по умолчанию** — ваш login-шелл в Unix. В Windows нет login-шелла пользователя, поэтому TermGlass предпочитает pwsh, затем Windows PowerShell, затем cmd.

**Выбор шелла.** Нажмите на имя шелла в строке состояния, на стрелку рядом с кнопкой новой вкладки или `Ctrl+Shift+S`. В каждой строке имя и путь к исполняемому файлу, а теги `system`, `default` (шелл, выбранный вами явно) и `current` (работает в активной панели). Клик по строке меняет шелл активной панели; при наведении доступны *New tab*, *Split* (с зажатым Alt — вниз) и *Default*. С клавиатуры: стрелки, `Enter`, `Shift+Enter`, `Alt+Enter`.

**Смена шелла** сначала запускает новый шелл в рабочей папке старого (читается из `/proc`, поэтому только Linux) и лишь потом завершает старый; если новый не запустился, панель остаётся нетронутой. История сохраняется. Подтверждение просится **только** когда в панели запущена программа, на пустом приглашении никогда.

**Настройки → Shells** показывают найденные шеллы с путями, шелл по умолчанию, поле *аргументов запуска* для каждого шелла и свои шеллы (любой абсолютный путь к исполняемому файлу, проверяется при каждом сканировании). Если сохранённый шелл по умолчанию пропал, новые сессии используют шелл системы, и об этом выводится уведомление.

Аргументы запуска разбираются небольшим парсером с поддержкой кавычек в массив аргументов и передаются прямо в вызов запуска PTY: никакой шелл их не интерпретирует, поэтому `;`, `|` или `$(...)` это просто текст.

## Темы

Встроенные: **TermGlass Dark** (по умолчанию), **TermGlass Light**, **OLED Black**, **Graphite**, **Frost**. Модульные тесты проверяют читаемость каждой палитры (контраст текста ≥ 7:1, цвета ANSI ≥ 3,5:1), а `minimumContrastRatio` в xterm задан для каждой темы как страховка.

Свои темы — файлы `.json` в папке тем (Linux: `~/.config/TermGlass/themes/`, открывается из **Настройки → Themes**). Они подхватываются сразу после сохранения; некорректные файлы не применяются, а показываются в списке с причиной.

```json
{
  "id": "midnight-ink",
  "name": "Midnight Ink",
  "type": "dark",
  "ui": { "accent": "#b69cff" },
  "terminal": {
    "background": "#0d0f1a",
    "foreground": "#dfe3f5",
    "cursor": "#b69cff",
    "red": "#ff7a93",
    "green": "#9be3b0",
    "blue": "#7ea6ff"
  }
}
```

Обязателен только `type` (`"dark"` или `"light"`). Недостающие цвета терминала берутся из TermGlass Dark/Light, а цвета интерфейса выводятся из палитры терминала. Цвета: `#rgb`, `#rrggbb`, `#rrggbbaa`, `rgb()` и `rgba()`. Ключи терминала: `background foreground cursor cursorAccent selectionBackground black red green yellow blue magenta cyan white` и варианты `bright*`. Ключи интерфейса: `background surface foreground muted border accent`. Необязательный `minimumContrastRatio` (1–21) переопределяет значение по умолчанию. Больше примеров в [`themes-examples/`](themes-examples).

## Настройки и данные

Тема, акцентный цвет, шрифт (семейство, размер, межстрочный интервал), форма и мигание курсора, шеллы (по умолчанию, свои, аргументы запуска), флаг login-шелла, рабочая папка по умолчанию, размер истории, прозрачность окна, размытие фона, анимации (полные / сокращённые / выключены), строка состояния, GPU-отрисовка и все сочетания клавиш. Всё хранится локально и проверяется при загрузке: неизвестные ключи отбрасываются, значения вне диапазона приводятся к допустимым.

| Что | Linux | Windows |
| --- | --- | --- |
| Настройки | `~/.config/TermGlass/settings.json` | `%APPDATA%\TermGlass\settings.json` |
| Свои темы | `~/.config/TermGlass/themes/` | `%APPDATA%\TermGlass\themes\` |
| Размер окна | `~/.config/TermGlass/window.json` | `%APPDATA%\TermGlass\window.json` |

## Особенности платформ

**Linux, Wayland, KDE Plasma.** В сессии Wayland Electron автоматически выбирает нативный Wayland. Окно без системной рамки, с собственной шапкой и кнопками. Пункт *Настройки → Appearance → Translucent window* создаёт окно с прозрачной поверхностью, чтобы ползунок **Transparency** показывал рабочий стол сквозь окно (нужен перезапуск). Размытие за окном — функция композитора: включите эффект *Blur* в KWin и добавьте в него класс окна `termglass`. Если прозрачное окно у вас рисуется чёрным, запустите `termglass --opaque` или задайте `"translucentWindow": false` в `settings.json`.

**Иконки промпта** (Starship, Powerlevel10k) требуют установленный Nerd Font. TermGlass находит установленные Nerd Fonts через fontconfig и использует их как запасные; ничего не встраивается. В Windows Nerd Font нужно выбрать шрифтом терминала самостоятельно.

**Windows.** Системные кнопки окна рисует `titleBarOverlay`; прозрачность использует acrylic и требует Windows 11 22H2+ с включённым *Background blur*. Определение запущенной программы (для подтверждения закрытия) опирается на процесс переднего плана PTY, который node-pty отдаёт в Linux и macOS, но не в Windows; там используйте *Confirm before closing → Always*. Всё это не проверялось.

## Архитектура

```
src/
  main/            Главный процесс Electron: окно, менеджер PTY, поиск шеллов, хранилища настроек и тем, IPC
  preload/         Изолированный preload с узким типизированным API в window.termglass
  shared/          Типы, каналы IPC, темы, проверка настроек, сочетания клавиш (без зависимостей от Node и DOM)
  renderer/
    components/    Интерфейс на React: шапка, вкладки, панели, палитра, выбор шелла, настройки, диалоги
    hooks/         Сочетания клавиш, оформление (тема в CSS-переменные и параметры xterm)
    state/         Небольшие внешние хранилища, логика дерева панелей, команды
    terminal/      TerminalSession (связка xterm и PTY) и реестр, без React
    styles/        Дизайн-токены и CSS
```

- **Вывод терминала никогда не попадает в состояние React.** Данные PTY идут main → IPC → `TerminalSession.write()` → xterm. React лишь размещает DOM-элемент сессии.
- **Панели — плоский список**, позиции берутся из дерева разделений, поэтому разделение или закрытие панели никогда не перемещает и не пересоздаёт canvas другой панели.
- **Обратное давление.** Вывод PTY склеивается (примерно 4 мс или 64 КБ на сообщение); PTY приостанавливается, когда около 1 МБ не подтверждено, и возобновляется по мере обработки xterm.
- **Один PTY на панель**, им владеет главный процесс; рендерер ссылается на PTY только по UUID.
- **WebGL только для видимых панелей**; скрытые вкладки освобождают контекст, а если WebGL недоступен, xterm переходит на DOM-отрисовку.

## Модель безопасности

- `contextIsolation: true`, `nodeIntegration: false`, `sandbox: true`, `webviewTag: false`; preload отдаёт один типизированный объект и никогда не передаёт странице сырые события IPC.
- Строгая Content-Security-Policy, навигация и `window.open` запрещены, все запросы разрешений веб-страницы отклоняются.
- Каждый обработчик IPC проверяет, что отправитель — собственный верхний фрейм приложения, и валидирует данные. Канала, выполняющего произвольные команды, **нет**: рендерер может лишь запросить PTY по **id** шелла (никогда по пути), менять размер, писать и завершать PTY по UUID, пользоваться буфером обмена, открывать ссылки `http(s)`/`mailto:` и менять проверяемые настройки.
- Шеллы запускаются с очищенным окружением (без `ELECTRON_*`, `npm_*` и переменных dev-сервера) и с `TERM=xterm-256color`, `COLORTERM=truecolor`, `TERM_PROGRAM=TermGlass`.
- Файлы своих тем ограничены по размеру, каждый цвет проверяется.

## Разработка

```bash
npm install
npm run dev          # dev-сервер Vite + esbuild watch + Electron с автоперезапуском
npm run typecheck
npm run test:unit    # раскладка, нечёткий поиск, настройки, темы, сочетания, поиск шеллов (подделки Linux, Windows, WSL)
npm run build
npm run test:e2e     # управляет собранным приложением; нужны дисплей и bash + zsh + fish
```

`npm run test:e2e` запускает собранное приложение через драйвер Playwright для Electron во временных `HOME` и каталоге данных. Структура проекта и правила описаны в [CONTRIBUTING.md](CONTRIBUTING.md).

## Известные ограничения

- Одно окно (повторный запуск фокусирует его и открывает вкладку); сессии не восстанавливаются после перезапуска.
- Нет лигатур, протоколов sixel/изображений и мультиплексирования терминала.
- Бинарные отчёты мыши (`onBinary`) не пересылаются.
- Сохранение рабочей папки при смене шелла использует `/proc`, поэтому работает только в Linux.
- Версии шеллов не показываются: поиск никогда не запускает найденные шеллы.
- Шрифты выбираются по имени; JetBrains Mono встроен и всегда служит запасным.
